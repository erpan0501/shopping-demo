# 意图识别测试用例（20 题 · 客户视角版）

> 用途：以**真实客户口吻**验证当前 Agent 的意图识别效果。
> 设计来源：客服对话里的常见场景 —— 催发货、催物流、问退款、问支付方式、改地址、砍价、转人工，以及客户直接粘贴单号/甩数字的习惯。
> 规则层预期已用项目实际代码（`app/service/intent_service.py`）验证；FAQ/LLM 层标注「观察」的，取决于 Java 模糊匹配与 DeepSeek 兜底，请以实际返回为准。
> 前置：Java(:8080) + MySQL 已启动，Python Agent(:8000) 已启动，`.env` 已配置 `DEEPSEEK_API_KEY`。
> 接口：`POST http://127.0.0.1:8000/chat`，请求体 `{"question":"…","userId":1}`。
> 判断依据：返回 JSON 的 `matched` / `source` / `answer` 三字段。

## 快速判读

- `source=faq` → 规则判定 OTHER，Java FAQ 命中 ✅ 正常
- `source=order` → 规则（或 LLM 兜底）判定订单意图，走 Java 订单接口
- `source=llm` → 规则与 FAQ 都没命中，DeepSeek 兜底回答
- `source=fallback` → DeepSeek 调用失败（检查 `.env` 的 key 与网络）
- 第 15~20 题是**故意设计的客户真实盲区**，用于暴露当前规则对自然口语的覆盖不足：
  - 15、16、19 → 规则“过度识别”（误判，FAQ 被拦截或任意数字当单号）
  - 17、18 → 规则“识别不到”（漏判，依赖 LLM）
  - 20 → “功能缺失”（转人工未实现）

## 与上一版的区别

上一版偏测试人员书面问法（“查询已发货的订单”“如何查询我的订单？”）；本版全部改为客户真实口语，同时保持对规则分支的覆盖，并新增了 3 个客户高频说法暴露的盲区（“在哪查我的订单啊”“我取消的订单去哪了”“这个能便宜点吗”）。
